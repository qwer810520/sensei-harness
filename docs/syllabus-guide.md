# 課綱撰寫指南

這份指南說明怎麼為 `sensei-harness` 寫一份課綱(`SYLLABUS.md`),讓引擎能照著它帶你上課。

搭配閱讀:[`courses/example-course/SYLLABUS.md`](../courses/example-course/SYLLABUS.md) 是一份完整的示例,本文提到的每條規則都能在裡面找到對應寫法。

---

## 開一門課需要什麼

| 檔案 | 誰寫 | 用途 |
|---|---|---|
| `LEARNER.md` | 你 | 你是誰、怎麼學、要防哪些壞習慣。從 [`LEARNER.example.md`](../LEARNER.example.md) 複製修改 |
| `courses/<slug>/SYLLABUS.md` | 你(或跟 Claude 一起編) | 這門課教什麼,本文的主題 |
| `courses/<slug>/PROGRESS.md` 等狀態檔 | 引擎 | 進度、成績、岔路紀錄,由引擎在上課過程中維護,你不用事先建立 |

`<slug>` 是課程代號,用小寫英數與連字號,例如 `rust-basics`、`system-design-2027`。開場時跟引擎說這個 slug,它就只載入這一門課。

**隱私:** `courses/` 底下除了 `example-course` 之外的所有目錄都已被 `.gitignore` 排除,再由 `.githooks/pre-commit` 二次攔截。你的課綱、進度與成績會留在本機,不會被推上 remote。

---

## 結構

### Frontmatter

```yaml
---
course: rust-basics          # 必須與目錄名稱(slug)一致
status: draft                # draft(編寫中)| active(上課中)| done(已結課);由你手動改,方便自己辨識,引擎不會擋 draft 的課
total_modules: 6
hours_budget: 5h/週          # 這門課預計每週排多少時間(規劃值,用來估每個模組要幾週)
phases:
  - {name: Phase 1, modules: 1-4, note: 基礎}
  - {name: Phase 2, modules: 5-6, note: 實戰,視能量插入}
excluded_globally: [unsafe Rust 深水區]   # 整門課都不碰的主題;沒有就寫 []
---
```

### 通則(放在所有模組之前)

寫全課共用的規則。示例課綱裡的三條是每門課都該有的:

- 每模組固定六欄:目標 / 概念 / 實作 / 驗收 / 錨點 / 不學
- 「錨點」寧缺勿硬掛;「不學」是模組硬邊界,全域硬邊界收在 frontmatter
- 能量 / 停損的個人數字不寫在課綱,由引擎讀 `LEARNER.md`

視需要可以再加,例如:

- **配比:** 每模組約「概念 2–3h + 實作 4–5h」,概念只讀當模組掛的主題
- **暖身:** 每模組開場 2–3 題簡單練習題,當暖身不當主菜
- **前置需求:** 全課共用的工具、版本、帳號,例如「Python 3.12+、一個 GitHub 帳號」

### 模組

模組標題用 `### M<編號>|<標題>`,編號從 1 開始連續。想分階段可以加 `## Phase 1|<名稱>` 當段落標題(選用)。

每個模組固定六欄,**欄名不要改**:引擎靠欄名找到對應的欄位,例如「實作」欄決定哪些東西必須由你自己寫。

```markdown
### M1|<標題>

目標:<一句話,學完能做到什麼>

概念:
- <這個模組要理解的東西,一條一個主題>

實作:
- <具體的產出物>

驗收:
- [ ] <口試題>

錨點:
- <新概念> ↔ <你已經熟的東西>

不學:
- <這個模組刻意不碰的深水區> —— <為什麼不碰 / 碰到時怎麼處理>
```

## 六欄怎麼寫,以及引擎拿它做什麼

| 欄位 | 怎麼寫 | 引擎怎麼用 |
|---|---|---|
| **目標** | 一句話,寫「學完能做到什麼」,不寫「學了什麼」 | 判斷這個模組有沒有走偏 |
| **概念** | 只放這個模組要讀的主題。每條寫成一個可被考的單位;同類的幾個小點可以放同一條,但驗收題要考得到它們 | 講解的範圍。超出範圍的岔路記進 `PARKING.md`,不展開 |
| **實作** | 寫具體產出:「寫一個 ≤30 行的 X」比「練習 X」好。每條都要能判斷「做完了沒」 | **這是你的主角戲。** 引擎不替你寫實作碼,只給測試、方向和骨架 |
| **驗收** | 口試題,用 `- [ ]` 列出(見下方「驗收題怎麼出」) | 口試題庫。答錯的題目進重考佇列,連過兩次才出列 |
| **錨點** | `新概念 ↔ 你熟悉的東西`,對應 `LEARNER.md` 的錨點庫存 | 講新概念前先掛錨點,再給抽象定義 |
| **不學** | 這個模組最容易讓你岔出去的深水區,附一句理由 | 你岔出去時,引擎一句話把它停進 `PARKING.md` |

### 驗收題怎麼出

驗收題就是口試題。好的驗收題考的是**理解**,不是記憶:

- **問「為什麼」,不只問「是什麼」。** 「X 是什麼?」只驗記憶;「為什麼要 X,不用 Y?」才驗理解。
- **要求舉例或反例。** 「什麼情況下這不成立?」「舉一個非用 X 不可的例子。」
- **少用二選一。** 「A 還是 B?」猜也有五成。真要用,把分數放在「為什麼」。
- **能連回實作最好。** 「挑一題你寫的實作,逐段解釋它在做什麼。」

示例課綱 M1 的驗收題可以對照著看:有預測結果再解釋差異的、有要求舉出非用不可的例子的,最後一題是拿自己的實作逐段解釋。

## 四條不變式

寫完課綱,用這四條檢查一遍。

1. **覆蓋不變式:每一條「概念」至少對應一題「驗收」。**
   沒有驗收題的概念進不了重考佇列,總考也掃不到,等於沒學。
   檢查方法:逐條看「概念」,替每一條指出是哪一題「驗收」在考它。指不出來就補題。驗收題數至少要等於概念條數。
   「挑一題實作逐段解釋」這類泛用題很有價值,但**不算覆蓋**,因為它不保證考到任何一條特定的概念。
   對照表貼在對話裡給自己或教練看就好,不必寫進課綱檔。

2. **錨點寧缺勿硬掛。**
   找不到自然的錨點就留白,或寫一句「本模組錨點稀薄,直接學」。牽強的類比會帶來錯誤的心智模型,比沒有更糟。

3. **「不學」掛在最誘人的相鄰模組。**
   只跟某個模組有關的深水區,寫在那個模組的「不學」。整門課都不碰的主題寫進 frontmatter 的 `excluded_globally`,再到最容易岔出去的那個模組的「不學」點名一次,標上「(全域硬邊界)」,示例的 M2 就是這樣寫。

4. **個人數字不進課綱。**
   每天幾點收工、單題卡多久要換方法、一週最多能撐幾小時,這些個人硬上限寫在 `LEARNER.md`。課綱只描述「教什麼」。
   frontmatter 的 `hours_budget` 不算個人數字:它是這門課的**規劃值**,用來估長度,不是停損線。

## 開課前檢查清單

- [ ] `course` 欄位與目錄名稱一致
- [ ] 每個模組六欄齊全,欄名沒改
- [ ] 覆蓋不變式:每條概念都指得出對應的驗收題
- [ ] 每條實作都能判斷「做完了沒」
- [ ] **實作需要的東西都拿得到。** 資料來源、帳號、硬體、付費服務,開課前就確認存在。上到一半才發現拿不到,只能臨時改題
- [ ] 長度合理:照 `hours_budget` 估每個模組大約要幾週,總長度你能接受
- [ ] 已經寫好 `LEARNER.md`,錨點欄引用的領域都在它的錨點庫存裡

---

## 開課之後:修訂與結課

**課綱不是一次寫死的。** 上課過程中引擎發現某個模組太易、太難或順序錯,它只能**提案**,不能自己改。你批准之後它才動手,並在課綱檔尾的 `## Changelog` 記一行,格式是 `YYYY-MM-DD|說明`,新的放上面:

```markdown
## Changelog

- 2027-03-02|M3 實作改用公開資料集:原定資料來源需要付費帳號。已批准。
- 2027-02-15|初版。
```

**結課條件:** 所有模組的驗收 PASS、結課總考 PASS、所有實作都有產出。三者達成後把 `status` 改成 `done`,引擎會產出一份成績單摘要。

## 用 Claude 一起編課

不想從零手寫的話,可以在這個 repo 裡開 Claude Code,把下面這段貼給它。它會先問你問題,再產出符合本指南的課綱。

```text
我想用 sensei-harness 開一門新課,請幫我編課綱。
這是編課,不是上課:不要執行 CLAUDE.md 的開場協議,也不要建立 PROGRESS.md 等狀態檔。

請先讀這三個檔案:
- docs/syllabus-guide.md(課綱規範)
- courses/example-course/SYLLABUS.md(示例)
- LEARNER.md(我的背景與錨點庫存;如果還沒有這個檔,先改讀 LEARNER.example.md,並提醒我先寫好 LEARNER.md)

在產出任何東西之前,先一次問我這些問題:
1. 想學的是什麼領域或技術?
2. 學完之後要能做到什麼?(具體的能力或產出,不是主題清單)
3. 期限,以及每週能投入幾小時?(用來決定模組數量和每個模組的份量)
4. 這個領域我已經會什麼、完全沒碰過什麼?
5. 有沒有刻意不想碰的深水區?
6. 實作需要的資料、帳號、工具,我手上有哪些?

拿到答案後:
- 依 docs/syllabus-guide.md 的結構產出 courses/<slug>/SYLLABUS.md,slug 跟我確認
- 寫完後在對話裡逐條列出「概念 → 對應的驗收題」對照表,證明覆蓋不變式成立(泛用的「解釋你的實作」題不算)
- 錨點只用我 LEARNER.md 錨點庫存裡有的領域,找不到就留白,不要硬掛
- status 設為 draft,等我看過再改成 active
```

課綱寫好、`status` 改成 `active` 後,開一個新的 Claude Code session,跟它說「開始上課,課程是 `<slug>`」就可以了。
